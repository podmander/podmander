# ADR-0043: Enrollment secret from getrandom(2)

**Date**: 2026-06-14

## Context

The enrollment secret — the credential that gates agent registration and stack
submission — was generated by `Ada.Numerics.Discrete_Random`, which in GNAT
15.2.1 seeds its Mersenne Twister from `System.Random_Seed.Get_Seed`, a
wall-clock-time-derived 32-bit value. This gave the secret at most 32 bits of
effective entropy, with the seed space wrapping every ~4.3 seconds. An attacker
who could estimate the controller's first-start time could narrow the candidate
set sharply.

`Secret_Matches` is the only gate on `Handle_Registration_Request` and
`Handle_Stack_Submission`. Recovering the secret lets an attacker enroll a rogue
agent and submit arbitrary stacks (i.e. deploy workloads on the fleet).

The CURVE keypair used for transport encryption is generated by CZMQ/libsodium
and was not affected — only the enrollment secret was weak.

## Decision

We will generate the enrollment secret from the Linux `getrandom(2)` syscall
rather than `Ada.Numerics.Discrete_Random`.

1. **Bind `getrandom(2)` directly** via `Interfaces.C` with `Import => True`.
   On Linux this draws from the same kernel CSPRNG that libsodium's
   `randombytes_buf` uses internally, so it is equally secure, but keeps this
   security fix self-contained — no cross-repo czmq_ada release on the critical
   path.

2. **Split the concern** so the testable part is pure and the untestable part
   is a thin, reviewed adapter:
   - `Bytes_To_Hex` is a deterministic, pure function: fixed input bytes →
     expected hex string. It is covered by a unit test that pins the encoding
     and proves the nibble mapping is correct and unbiased.
   - `Get_Random_Bytes` is the `getrandom(2)` adapter. It checks the return
     value, loops if fewer bytes than requested are returned (defensive), and
     raises `CSPRNG_Error` on failure. It never falls back to a non-CSPRNG
     source.
   - `Random_Hex` composes the two: obtain random bytes, convert to hex.

3. **No black-box randomness test.** A non-repeat / "successive secrets differ"
   assertion is deliberately not written: it passes on the vulnerable
   time-seeded implementation too (two sequential calls read different clock
   values), so it has no power to distinguish broken from fixed. The CSPRNG
   guarantee rests on the implementation (it draws from `getrandom(2)`) plus
   code review and this ADR.

4. **Fail loud, never weak.** If `getrandom(2)` returns -1, `CSPRNG_Error` is
   raised. There is no fallback to any non-cryptographic source.

## Consequences

### Positive

- Enrollment secrets now have full 128-bit entropy from the kernel CSPRNG.
- The seed space no longer wraps every 4.3 seconds; secrets are not
  time-correlated.
- The byte→hex transform is independently testable with deterministic
  assertions.
- The fix is self-contained in `Podmander.Enrollment` — no dependency changes,
  no cross-repo coordination needed.

### Negative

- The `getrandom(2)` binding is Linux-specific. This is acceptable because the
  deployment target (systemd + Podman) already implies Linux.
- The `getrandom(2)` adapter cannot be unit-tested in isolation (it calls the
  kernel). The CSPRNG guarantee is carried by implementation review and this
  ADR rather than by a test assertion.

### Neutral

- The public API (`Ensure_Secret`, `Get_Secret`, `Secret_Matches`,
  `Generate_Join_Token`, `Parse_Join_Token`) is unchanged.
- `Bytes_To_Hex` and the `Byte`/`Byte_Array` types are added to the public
  spec to enable deterministic testing.

## Alternatives Considered

### libsodium `randombytes_buf` via czmq_ada

- Pros: single in-process entropy source (CZMQ/CURVE already uses libsodium);
  portable across platforms.
- Cons: requires a czmq_ada release with a CSPRNG API (tracked as czmq_ada#18);
  adds a cross-repo dependency to this security fix.
- Why deferred, not rejected: once czmq_ada#18 ships, the local `getrandom`
  binding can be swapped for the libsodium call. This is a non-breaking
  internal change. Tracked for future consolidation.

### Reading `/dev/urandom` as a file

- Pros: no syscall binding needed; portable across Unixes.
- Cons: adds file descriptor handling (open, read, close); introduces
  chroot and fd-exhaustion edge cases that `getrandom(2)` avoids; the
  syscall is the more direct interface on Linux.
- Why rejected: `getrandom(2)` is simpler and avoids fd lifecycle concerns.
